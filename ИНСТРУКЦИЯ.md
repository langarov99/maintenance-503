# Data Extraction Bot — Инструкция за употреба и възстановяване

## Какво прави бот-ът

Чете PDF или Excel файлове от OSRAM (и други доставчици) и извлича продуктова информация
в структуриран Excel файл с колони: Код, Количество, Единична цена, Обща сума, Описание, EAN, Тегло.

Автоматично търси в локалната база данни (`data/suppliers/`) и допълва продуктовия код
(напр. `LEDIL432`) по AM артикул или EAN.

## Употреба

1. Отвори http://localhost:5000
2. Избери файл (PDF, XLSX, XLS, CSV, TXT, PNG, JPG...)
3. Избери езици за OCR ако е нужно (по подразбиране: bg, en)
4. Натисни "Извличане"
5. Изтегли резултата като Excel файл

### Проверка на здравето на бота
Отвори: **http://localhost:5000/health**

Трябва да видиш нещо подобно:
```json
{
  "status": "ok",
  "llm_available": false,
  "db_loaded": true,
  "db_by_code": 1250,
  "db_by_ean": 961
}
```
Ако `db_by_ean` е 0 — провери дали файлът `osram-export-all-ean-code.xlsx` съществува
и дали колоната с EAN кодовете е форматирана като текст (не научна нотация).

## Известни особености на OSRAM документи

- AM/AA артикул кодовете (`AM507120055`) се ползват САМО за DB lookup — не се показват като продуктов код
- Продуктовият код (`OJS030`, `LEDIL432`) се извлича от позиционния ред на фактурата
- EAN е на същия ред като AM кода — търси се само в ±2 реда за да се избегне "изтичане" от предишен продукт
- Позиционни редове: формат `000020`, `001110` или `80-002`
- Ако два AM кода сочат към един и същи вътрешен код — запазва се записът с повече данни

## Честа диагностика

| Проблем | Проверка |
|---------|----------|
| `db_by_ean: 0` | Файлът `osram-export-all-ean-code.xlsx` липсва или EAN колоната е в научна нотация |
| Грешен продуктов код | Провери дали DB файловете са актуални |
| Малко извлечени записи | Виж конзолата — `dropped ... no quantity found` показва пропуснатите |
| Дублирани редове | Актуализирай до последния commit (v1.1+) |
| Бот не се стартира | Провери дали порт 5000 е свободен; провери зависимостите с `pip list` |
